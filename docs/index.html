Backups you can open with tar.

Shoebox copies your server's folders and MySQL/MariaDB databases to Dropbox every night, checks every file, and emails you the result. The backups are plain .tgz and .sql.gz files, so you can read them on any machine, years from now, without Shoebox.

Simple on purpose, careful where it counts

A second copy you can always read, next to restic or Borg, or the only backup a small server needs.

Dumps that are checked

A dump only counts if mysqldump exits cleanly, the file ends with -- Dump completed, and it has one CREATE TABLE for every table. --force is never used.

Uploads that are verified

Every file is compared with Dropbox's own content_hash after upload. Big files go up in chunks, with retries.

Any MySQL or MariaDB

On this machine, another host, or inside a Docker container. Each server has its own login and databases; nothing is assumed.

No secrets on show

Passwords live in a root-only .env and reach the database through the environment, never the XML or a command line.

Sensible retention

Keep the newest run of each of the last 14 days, 8 weeks and 12 months, or any mix. Nothing is deleted after a bad night.

A report every morning

An HTML email with every folder, database and upload, a status file for monitoring, and an exit code equal to the number of errors.

What happens each night

One run, in this order. A problem with one folder or database is reported and the rest carries on.

  1. ArchiveEach folder becomes a .tgz, or one per site with split folders.
  2. DumpEach database is dumped, compressed and checked table by table.
  3. ManifestSize and SHA-256 of every file go into manifest.json.
  4. UploadFiles go to your Dropbox app folder and are hash-checked.
  5. TidyOld runs are thinned out in Dropbox and removed locally.
  6. ReportYou get an email, and monitoring gets status.json.

Get started in four steps

About fifteen minutes on a Linux server with Python 3.8 or newer. The README covers every option.

1. Install

Clone it and copy the two example files.

sudo git clone https://github.com/gelvogit/shoebox-backup.git /opt/shoebox
sudo ln -s /opt/shoebox/shoebox.py /usr/local/bin/shoebox
sudo install -d -m 700 /etc/shoebox
sudo cp /opt/shoebox/backupconfig.example.xml /etc/shoebox/backupconfig.xml
sudo install -m 600 /opt/shoebox/.env.example /etc/shoebox/.env

2. Connect Dropbox

Create an App-folder app at dropbox.com/developers, tick four permissions, then log in. Step by step

sudo shoebox auth     # open the link, click Allow, paste the code

3. Say what to back up

Folders and database servers go in backupconfig.xml. Passwords go in .env.

<folder>
  <folder_label>WWW</folder_label>
  <folder_path>/var/www/html</folder_path>
  <folder_split>yes</folder_split>       <!-- one archive per site -->
</folder>

<database_server>
  <label>shop</label>
  <docker_container>shop-db</docker_container>
  <username>root</username>
  <password_container_env>MARIADB_ROOT_PASSWORD</password_container_env>
</database_server>

4. Check, test, schedule

Fix any FAIL lines, prove a restore works, then add one cron line.

sudo shoebox check
sudo shoebox run --no-email
sudo shoebox restore latest --target /tmp/restore-test

# root's crontab: every night at 00:30
30 0 * * * /opt/shoebox/shoebox.py run > /dev/null

Is it right for you?

A good fit

  • A Linux server or VPS with websites, config and a few databases
  • A Docker host running MySQL or MariaDB containers
  • A readable second copy next to an encrypted backup tool
  • A few GB a night, with an email that says it worked

Look elsewhere if you need

  • Encryption at rest: Shoebox files are plain by design
  • Hundreds of GB, or incremental and deduplicated backups
  • PostgreSQL, Windows, or storage other than Dropbox
